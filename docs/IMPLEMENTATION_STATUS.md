Nothing below claims production readiness. No module has been used by a real school. All data is synthetic.

## Known limitations

1. Both container images build in CI. The full container stack has not been run on Windows or macOS, and `--dev` mode is verified on Linux only.
2. The scripts have been behaviour-tested with a Docker stand-in on Linux and PowerShell 7 on Linux; first real runs on Windows (5.1 and 7) and macOS may surface environment differences.
3. The campus switcher changes the scope bar but does not filter lists yet (single-school pilot makes this low priority).
4. Parent phone sign-in (ADR 0009) is built and verified in CI, but no real SMS provider is connected (see 13). Staff sign-in through OIDC is built but has not been tried against a real identity provider (see 14).
5. Hindi strings are partial and need native review; the State-board language (e.g. Kannada, Tamil) depends on which state is chosen.
6. A mobile app exists (`mobile/`, section B9 below) and its core library is tested in CI, but it has never run on a real phone, and ADR 0005 is still Proposed until it does. Most staff features (approvals, visitors, facilities, compliance, workflow and others) are web only.
7. `config_version.value` is checked server-side only for known keys (`attendance.late_after_minutes`, `assessment.grade_scale`, `flag.*`); other keys accept any JSON.
8. B1 web offers add/remove for terms and add for the rest; renaming grades, retiring subjects and changing section capacity exist in the API but not yet as web controls. Rollover never edits the source year, so final-grade students stay ENROLLED there until the year is closed.
9. Import file contents are kept in `import_batch.file_table` to re-check plans at commit (retention class TRANSIENT; a purge job is not built yet).
10. The web bundle is 102.0 kB gzip of the 120 kB budget (D8). Every page loads on demand; the main bundle is the shell and shared code.
11. Fixed earlier: wide tables made the whole page scroll sideways on phones (grid column blowout); the dev backend now runs a copy of the jar from `.run/`, so `mvn verify` can no longer replace the jar under a running JVM (seen here as a hung API).
12. B4 API: CI compiled it and ran it green after one test bug was fixed.
13. Sign-in codes are only "sent" to the backend log (console adapter, dev only). A real Indian SMS provider needs TRAI DLT sender and template approval, which can take weeks (ADR 0009); until then no parent can sign in outside local development.
14. Staff sign-in (OIDC) is configured per environment and not exercised here; the admin and finance second-factor check reads the `amr` claim and needs a provider that reports it.
15. Sessions are per phone number, not per school: ending a guardian's sessions in one school ends that number's sessions everywhere. Sessions are kept after a relationship ends (the identity then has no children). A refresh response lost on a bad network makes the retry look like a replay and ends the session; the parent signs in again with a new code. Unknown-number challenges are stored (so limits and timing match) and are not purged yet.
16. Web attendance keeps unsent marks in memory only (child data is not written to browser storage); closing the tab loses unsent marks. Durable offline storage belongs to the Android app (B9).
17. The notice dispatcher runs inside the API process on a 15-second poll. The cross-school SQL functions it calls run as the schema owner and are granted to the application role, so a compromised application could ask for due SMS (phone numbers and generic text) across schools; a separate worker role is the planned hardening before production.
